# 语义分类与去重解耦

2026-11-19 用户确定的流程：

1. BGE 编码器和训练分类头对分类单元推理，使用分类头 `predict_proba` 的最高概率。
2. 概率 **≥ 0.75** 且类别属于客户包类别集合时，直接采用。
3. 概率 **< 0.75**、输出类别不适用、新类别或 BGE 不可用时，交给 `event_classifier` 大模型复判。
4. 大模型明确返回 `uncertain` 才列入“待人工分类”。接口失败、漏项、重复 ID、非法类别等不是业务不确定，显示“模型尚未处理”，继续重试。

不再因为命中词表或源表已有分类，就跳过 BGE 和语义复判。词表工具仍保留为兼容工具和中间候选，不决定最终审核分类。

## 去重开关

| 配置 | 分类单位 | 归并产物 |
|---|---|---|
| 自动分类开、去重关 | 每条负面或预警原始记录 | 不创建 `group_events` 或 `event_analysis`；保存独立 `semantic_classification` |
| 自动分类开、去重开 | 完成事件归并后的最终事件 | 在事件分析中调用同一个三级分类执行器 |
| 自动分类关 | 不执行 BGE 或分类大模型 | 去重、TOP10 等独立开关照常生效 |

人工指定分类保持优先，合并后存在不同人工分类时保持待人工处理。分类人数统计实际单位为分类单元，单元下的 `member_ids` 保留原始记录映射。

## 部署配置

客户包 `manifest.yaml` 声明 `features.event_classification.enabled` 及 `stages` 中的 `bge`、`llm` 开关、BGE 阈值；模板级开关仍与客户包开关相与。

机器路径与凭据只写部署 `.env`：

```dotenv
CLASSIFY_PYTHON=D:/miniconda3/envs/bge/python.exe
CLASSIFY_ENCODER=D:/BGEembdding/output/anshun_ft/final
CLASSIFY_HEAD=D:/BGEembdding/output/anshun_head/head_best.joblib
CLASSIFY_TIMEOUT=600
CLASSIFY_BATCH=32
CLASSIFY_THREADS=4
```

本机模型依赖留在 BGE 环境中；工作台以 JSON 标准输入输出调用独立工作者，CPU 线程上限为 8、默认 4，模型只从本地加载。工作者校验分类头记录的编码器路径必须匹配配置编码器。只加载本机可信训练产物。

也支持远程 `CLASSIFY_BASE_URL`、`CLASSIFY_API_KEY`，URL 非空时优先远程；请求契约仍为 `POST /classify`。大模型复判沿用工作台现有生成模型配置，角色为 `event_classifier`，不同于 `data_processor` 工具规划。

本机分类头含 15 类，龙川模板采用安顺 12 类；不属于模板集合的预测一律转大模型，不自动合并或改写类别。

## 审计、断点和确认

- 逐单元记录最终来源、状态、理由、原始 BGE 类别与置信度，以及可用的模型信息；本机工作者记录分类头 SHA-256。
- `semantic_classification_checkpoint` 保存已完成的 BGE 和 LLM 结果。相同输入重试复用成功结果；输入、成员、类别集合、阈值、提示词或部署模型标识变化会使对应缓存失效。
- BGE 技术失败允许再次尝试；有效的低置信度 BGE 结果不因 LLM 失败而重复计算。
- `classification_stage`、`semantic_classification_progress`、`semantic_classification_summary` 事件显示执行与计数；审核接口返回 `classification_counts`，区分 BGE、LLM、待人工和模型未完成。
- 模型尚未完成时，前后端均不允许以人工改分类绕过模型完成门禁。完成后仍由用户审阅并确认，不自动锁定事实。
- 已确认模板、已有冻结报告保持原样。本次不自动重跑现有业务任务。

## 现有龙川任务的使用方式

现有 282 条“待人工分类”是旧词表流程的结果，不能算两轮模型后的人工待办。重启后，在该任务点击“按新规则重新处理”。程序会对本期全部负面或预警分类范围重新执行三级分类，而不是只处理旧的 282 条；BGE 达标的跳过大模型，复判仍不确定的才进入人工。

已有 `event_analysis` 的旧去重任务可通过现有事件设置的“重新处理”入口重建分析；被冻结的报告不自动重新分类。
