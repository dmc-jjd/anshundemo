所有提示词继续集中在 `app/agent.py`。新增 `RISK_COMPARISON_PROMPT`，并更新研究、Writer、模板政策的对应要求，程序Schema与校验同步调整。

流程为：**模型知识比较至少4类候选 → 复用已有资料、按缺口核实地方事实 → 选择3—4类未来风险 → Writer写自然完整段落 → 本地校验和人工终审**。

比较阶段没有联网工具，必须给出4—8个不同候选、季节/节庆/习俗/产业/本月信号因素、知识依据、比较理由及需核实的地方事实。核实阶段才提供Search/Fetch工具，不强制搜索次数，也不按10年逐年普查；历史优先近3年、最多5年。

| 依据性质 | 接受方式 | 表述限制 |
|---|---|---|
| historical | 可核实的本地历史同期案例、跨年复现或官方高发资料 | 单案只作参考；跨年证据才称复现；高发需相应证明 |
| seasonal | 本地季节资料，或有明确适用月份的知识与条件推演 | 不能把一般机制说成本地已确认高发，不能虚构历史案例、数量和日期 |
| local_activity | 已阅读、可核实的地方节庆、习俗、产业或活动来源 | 不能仅凭模型记忆断言当地已经安排或一定集中举办 |

不再要求三类全部具有历史高发证据。没有直接地方活动依据时，可提出“若未来窗口举办相关活动”的季节风险，清楚说明假设；不能把2月春节材料写成11—12月同期。知识推演单独保存为risk_knowledge引用，在证据页标明性质，不伪造网页来源。

Writer必须提供每项paragraph自然正文，审计字段用于核对，不再让省略正文后拼接字段成为正式写作路径。缺乏依据的高发表述继续拒绝，但“不作高发认定”等否定表述不应被误拦；完整Schema错误会精简逐条反馈，不截掉后半批问题。

提示词缓存按字段依赖区分。调整研究/建议提示词只使工作建议机器稿失效，第一部分和研判段保留；人工文字始终优先。

# 为什么界面通常显示“事件甲、乙”

这是一次关系判断的两个输入，输入可以是已经含多条记录的事件组。多条记录分别达到固定代表向量阈值，可以进入同一组；模型的边界关系比较和人工判断也可连续合并更多组。TOP10候选复核本身支持group_ids列表，并非只允许两个ID。

已核查最新任务的模型输入、输出与最终成员位置：

- event-120、event-121、event-111、event-1986、event-551、event-990、event-966，共7个候选组的代表记录最终进入event-120。
- event-103、event-295、event-363，共3个候选组的代表记录最终进入event-103。

这些是多个候选组被判断指向同一真实事件，并不意味着将不同真实事件按主题统一归类。界面现标注“事件组甲/乙”、当前记录数和代表内容，并说明连续合并支持更大的组。

浏览器模拟验证了甲乙先合并为2条，再与丙合并为3条，最终一个组、两项人工判断；该检查仅在测试页面内存中执行，未更改真实人工分组。已有真实7组合并和3组合并的证据另保存为JSON。
