## 3. 数据流

```
① 输入
  浏览器 app/static/index.html + app.js
    │ POST /api/files    （.docx/.xlsx，≤100MB，按 sha256[:20] 命名）
    ▼
  data/uploads/file-<sha256[:20]>.{docx,xlsx}

②-甲  模板链（kind=template，≥2 份 docx）
  POST /api/template-tasks
    → workflow.run_template_graph → build_template_graph
      validate_input
        → tool.compare_report_structures
             ← template_compare.parse_report_document（每份 docx → blocks）
             ← template_compare.compare_reports（SequenceMatcher 结构对齐）
        → structured_template.build_structured_template（本地候选，不调模型）
        → template_review.make_input（组装模型输入包）
        → template_execution.review_batches（分批 × 最多 3 轮）
             ↺ template_validation.collect_errors → 退修 → 再校验
        → template_review.compile_review（编成模板候选）
      ▼
    工件 structured_template_ref + template_validation_ref
    人工 POST /api/templates/{id}/confirm
      ▼
    工件 confirmed_template_ref（template_version，不可变）──┐
                                                          │ 供报告链读取
②-乙  报告链（kind=report，1 份 xlsx，sheet_index 默认 3）  │
  POST /api/report-tasks → workflow.run_report_graph ◄─────┘
    validate_input
    → data_processing
        tool.import_records（读第 3 表 → records 工件）
        然后二选一：
          · metadata.mode == 'dynamic'：data_processor 模型逐轮自选工具
          · 否则：fallback_policy.build_fallback_plan 固定序列
                  + workflow._args_for 供参（含 scope 分支）
        工具：filter_records / resolve_locality / classify_records
              cluster_event_themes / discover_topics / select_materials
              group_events（event_grouping 本地余弦，不调模型）
        每次调用必经 tool_executor.execute_tool
          （白名单·阶段·预算·冻结·幂等·子进程超时）
    → event_analysis（event_analysis.analyse_events）
        模型：事件归并 → 事件分类 → TOP10 梗概（15–35 字）
        分阶段独立失败预算；结果落 event_analysis 工件
    → await_data_review（生成 data_review 审核项）

    人工① POST /api/tasks/{id}/confirm-data
      → storage.apply_decision（覆盖校验：成员唯一且全覆盖）
      → data_review.apply_human_review（本地重算，零模型调用）
      → workflow.freeze_facts
          ▼
        FactSnapshot（fact_ref，sha256 定版，此后状态不可变）

    → 写作图 workflow.build_writing_graph
      validate_input（要求 fact_ref）
      → write_draft
          · 结构化路径：structured_writer.write_structured_preview
              数据字段：frozen_report.calculate（确定性）
              文字字段：writer 模型 + source_binding 编号引用
              图表：writer_tools.chart_payload（Matplotlib）
          · 旧槽位路径：slot_writer.write_first_section_slots
              图表：tool.render_chart（Pillow）
      → local_validation（report_validation，确定性）
      → style_detection（style_skill 去 AI 表达检测）
      → format_review  → content_review（reviewers 双审核）
      → revise_draft（source_binding → reviewers 限次退修）
      → ↺ 各阶段 ≤5 次循环
      → final_format_review → await_final_review

    人工② POST /writing-review/{issue_id}/edit、/slot-values、
           /chart-settings、/report-parameters（均不回流模型）
    人工③ POST /api/tasks/{id}/approve（写 approval_hash）

③ 报告生成
  export.export_docx

## 7. 去重与分类的现状解剖

> 队长补充要求（用户明确：现有代码已含去重与分类算法，重构后要剥离为独立工具并换新算法）。
> 本节全部结论来自逐行阅读 `tool.py` / `event_grouping.py` / `event_analysis.py` / `frozen_report.py` / `data_review.py` / `storage.py`，附文件:行号。

### 7.1 去重

#### 7.1.1 逻辑分布

**先给结论：系统内没有「记录级去重」。** `import_records` 阶段逐行全收，`filter_records` 只按字段筛选也全收。
真正意义上的去重发生在**事件归并**（把多条记录收成一个事件组），不在导入、不在筛选。

| # | 位置 | 函数 | 具体做什么 | 粒度 |
|---|---|---|---|---|
| 1 | `app/tool.py:26-42` | `import_records` | **不去重**。仅跳过整行全空（`:34`）。记录 ID = `f'{file_hash[:12]}:{sheet}:{excel_row}'`（`:35`）——这是**行身份标识**，不是去重键 | 行 |
| 2 | `app/event_grouping.py:6-46` | `group_by_representative` | **主去重（本地算法）**：标题+梗概的双字词 TF-IDF 稀疏余弦，阈值 0.65，**只与不可变代表比较**（防链式误并），`best_score+1e-12 >= threshold` 则并入该组（`:30-31`） | 记录 → 事件组 |
| 3 | `app/tool.py:154-160` | `group_events` | 包装 #2，产出工件 `automatic_event_groups` | 事件组 |
| 4 | `app/event_analysis.py:107-219` | `analyse_events`（归并段） | **模型二次去重**：只对 `borderline_candidates`（相似度落在 0.39–0.65 的边界对）逐对问模型 `same/different/uncertain`，再用并查集合并；支持断点续跑 | 事件组 → 事件组 |
| 5 | `app/event_analysis.py:168-214` | `analyse_events`（TOP10 段） | **TOP10 专属去重**：`top10_deduplication` 阶段把前 30 名再交模型归并（prompt `event_judge.top10`），最多 3 轮；人工已判「不同」的对被列为 `cannot_merge` 禁并（`:179`） | TOP10 候选 |
| 6 | `app/event_analysis.py:63-73` | `negative_ranking` | TOP10 排序与组身份：只计「负面 **且** 预警」成员（`:66-67`，**交集不是并集**），按组内条数降序；组 `fingerprint = sha256(json.dumps(sorted(negative_ids)))`（`:72`） | 事件组 |
| 7 | `app/frozen_report.py:158-189` | `query_materials` | **材料选择期临时去重**：按 `title.strip()` 完全相同去重（`:179-180` `seen`）；`distinct_events=True` 时再按事件去重（`:182-183`）。只影响喂给 Writer 的材料清单，不改事实 | 记录 |
| 8 | `app/section_two.py:282-290` | `source_excerpts` | 原文摘录去重（`seen` 按 key 去重） | 文本片段 |
| 9 | `app/storage.py:117-124` | `apply_decision` | **人工确认时的完整性校验**：要求成员 ID 不重复**且**恰好覆盖全部源记录一次（`review_members_must_cover_records_once`）。这是「不许漏、不许重」，不是相似度去重 | 事件组 |

#### 7.1.2 去重键是什么

**不是 URL，不是时间窗，不是正文指纹。** 分四层，键各不相同：

| 层 | 去重键 | 判定方式 | 代码位置 |
|---|---|---|---|
| **事件组（主）** | `标题 + 梗概` 的**双字词（bigram）TF-IDF 稀疏余弦相似度** | 中文段按 2 字滑窗切 bigram、英文/数字按整词（`:12-14`）；权重 `count*(log((N+1)/(df+1))+1)` 后 L2 归一（`:18-20`）；**只与该组第一个成员**（`representative_index`，不可变）比余弦，`>= 0.65` 即并入（`:30-31`） | `event_grouping.py:6-46` |
| **边界候选** | 同上余弦，但阈值下探到 `threshold*0.6` = **0.39** | 落入 `[0.39, 0.65)` 的不自动合并，记入 `borderline_candidates` 交模型判（`:34-36`） | `event_grouping.py:34-36` |
| **TOP10 组身份** | `sha256(sorted(负面且预警成员ID))` → `fingerprint` | 组内容一变 fingerprint 就变，作为缓存与人工补梗概的对齐键 | `event_analysis.py:72`；消费于 `storage.py:139-143`、`data_review.py:83-86` |
| **材料级** | `title.strip()` 全等 | 完全相同才算重复（不去标点、不做归一） | `frozen_report.py:179-180` |
| 行身份（**非去重**） | `file_hash[:12] : sheet : excel_row` | 仅保证行唯一，天然不重复 | `tool.py:35` |

补充事实（影响换算法）：
- **没有时间窗**：跨日、跨月的相似标题会被同一个阈值处理（`event_grouping.py` 全文无日期参与）。
- **没有 URL 参与**：同 URL 不同标题不会被识别为同一事件。
- **代表不可变**：新记录只与组代表比，不与组内其他成员比，因此**不会链式传递**（`tests/test_event_grouping.py::test_representative_prevents_transitive_merge` 专门锁定该行为）。
- 作者自述口径：`docs/817与1688去重口径对比-20261108.md:32` 明确写「并非语义嵌入模型」。

#### 7.1.3 两套口径的差异（一句话）

> **817 = 人工按「规范化事件标题」做的等价类**（参考文件自带「是否重复」标记列，774 行标「否」、43 行仍标「是」，范围全为负面且预警）；
> **1688 = 机器按「标题+梗概双字词 TF-IDF 余弦 ≥0.65、只与固定代表比」聚出的组**（范围是负面并集）；
> **一句话：两套口径的事件粒度与统计范围都不同，所以 817 与 1688 的差是「口径差」而非「准确率差」。**

对账数字（均来自该文档，未重新计算）：

| 参考去重文件 | 817 行 = 817 个互不相同的规范化标题 | `:14` |
| 当前负面范围组数 | 1688 | `:10`、`:13` |
| 当前负面且预警组数 | 939 | `:11`、`:12` |

group_events         ── ★第一次去重：本地 TF-IDF 余弦 0.65     ← event_grouping.py
        ▼
event_analysis       ── ★第二次去重：模型判边界候选 0.39–0.65  ← event_analysis.py:107-219
                     ── ★TOP10 专属第三次去重（≤3 轮）          ← event_analysis.py:168-214
        ▼
人工确认             ── 只做「不漏不重」完整性校验，不再算相似度 ← storage.py:117-124
        ▼
confirmed_event_groups（事实层，冻结）
        ▼
query_materials      ── 消费期临时去重（标题全等 / distinct_events）← frozen_report.py:179-183
```

**结论**：去重是 `data_processing → event_analysis` 之间的**两级串联**（本地向量聚类 + 模型边界判定），
且**第三级 TOP10 去重独立存在于 event_analysis 内部**。剥离时必须同时处理这三段，不能只搬 `event_grouping.py`。
