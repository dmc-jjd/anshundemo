## Decided（本阶段定下、后续不得无据推翻的结论）

1. **`CORE-DEP = 0` 作为 S7 硬出口**（§6 D1/D3 取 (a)）。做法是「上移 + 注入」而非「让 core import app」：新增 4 个 core 文件（`core/paths.py`、`core/tools/contracts.py`、`core/tools/ooxml.py`、`core/tools/template_compare.py`），并在 `core/paths.configure_data_root()` / `core/charts/renderers/matplotlib.configure_report_factory()` 两个基础设施注入点上收口。15 处 → 0 处，六组门禁逐字符证明零行为漂移。
2. **两个基线各录一次、录后只读**（反自证纪律）。`--record` 目标存在即拒绝；`--force` 需队长书面批准。本次出口判定的准绳是 `core-S7-preB.json`，不是任何事后重录的文件。
3. **`ToolSpec` 上移但两类型不统一**（§6 D2 取 (b)）：pydantic `ToolSpec` 进 `core/tools/contracts.py`（消反向依赖），但**不**统一到 `core/ports.py` 的 frozen dataclass。`core/ports.py` 是 S1 冻结契约，本阶段零改动。
4. **`app/config.py:39` 保留 1 行注入**（§6 D4 取 (a)）：`PACKAGE = os.getenv('REPORT_PACKAGE', 'anshun_monthly')`。这是「只加包」在 **app 层**成立的唯一办法；默认值不变 → 既有 11 条门禁零变化。
5. **包 B 进 `packages/` 而不是 `tests/fixtures/`**（§6 D7 取 (a)）。它是「可扩展」的证据，必须与 A 并列为同级包，才能被 `test_s7_package_contract.py` 的「每个包」遍历面覆盖。
6. **B 故意与 A 数据不同**（3 张图 vs 5 张、2 类 `cluster_terms` vs 12 类、两个虚构片区 vs 安顺八区县）。相同则「换包成功」与「硬编码生效」在观测上不可区分，证据作废。
7. **`is_second_section` 数据化不做**（§6 D5 取 (b)）：它是 P4 的尾巴，做会让 `G-PROMPTS` + `G-SKILL` 双变并让 `test_s4_skill_parity.py` 红。归档，触发条件见 Remaining。
8. **伪 schema → 真 JSON Schema 不做**（§6 D6 取 (b)）：会让 `G-SPECS` 21 项序列化全变（必须 `--force` 重录）且改动模型输入，与 P7 零漂移冲突。转维护期。
9. **`main.py` 不拆 router**（S6 D5 + §6 D8 取 (b)）：拆它会让 `APP-HASH` 变，直接冲突 P7「宿主零改动」。
10. **B 的冒烟只在子进程加载**（RISK-1）：四个注册表都是 module-global，本进程 `configure(demo_b)` 会污染后续 300+ 用例。`test_s7_package_b.py` 全部走 `subprocess.run`。
11. **B 只跑 `mode='fallback'`**：`dynamic` 分支在 `app/workflow.py:207` 读死 `templates/anshun-colored/report.template.json`，走它会「跑通但跑的是 A 的数据」，构成 P7 的反例。

## Rejected（明确否决、并给出否决理由的选项）

| 选项 | 否决理由 |

## Risks（下一个人必须知道的风险与证据边界）

1. **R1｜基线时序瑕疵（新增发现）**：`app/config.py:39` 的 D4 注入点在 `2026/11/12 05:34:37` 落盘，**早于** `core-S7-start.json` 的 `recorded_at 05:43:13` 共 8 分 36 秒。后果：start 基线的 `APP-HASH fc8c9b75…` 严格来说是「D4 之后」而非「S7 之前」的快照，因此「start→preB 的 app 差异集」**不含** D4 这一处。**`core/` 不受影响**（最早 core 改动 `05:51:50` 晚于基线，`CORE-HASH 2146…` 是真·S7-前快照）；§4.5④ 的「加包前后相等」用 preB 做准绳，也不受影响。
2. **R2｜`dynamic` 分支的客户硬编码仍在**：`app/workflow.py:207` 读死 A 的模板路径。**包 B 从未走过 `dynamic`**，所以「换包即换系统」只在 `fallback` 分支成立。任何后续声称「P7 已证明任意模式换包可行」的说法都是过度外推。
3. **R3｜B 只覆盖 `report` 图**：B 的 `template.json` 无 `fields`/`blocks`/`skill_scope`（实测 False/False/False），`template` 图与 `writing` 图在 B 下**从未执行**。`PACKAGE-B-PASS` 严格限于 `validate_input → data_processing → event_analysis → await_data_review → phase='awaiting_review'` + 16 个 `result_refs`。
4. **R4｜进程内 `configure` 污染（RISK-1 未消失）**：四个注册表仍是 module-global。任何新测试若在本进程 `configure` 成 B，会以「部分用例随机红/绿、`pytest -k` 单跑又没事」的形式爆炸。B 的加载验证**必须**继续留在子进程。
5. **R5｜门禁自证循环（RISK-2 未消失）**：`gate_core_iso --record --force` 能把红基线刷绿。两份基线已录，**不得重录**；若必须重录，需队长书面批准并在报告里写明理由。
6. **R6｜规格与实测的 4 处字面偏差**（详见验收报告 §4）：①`CORE-FILES` 口径（含 1 个 `.json` → 32，而 `.py` 是 31）；②`REFS` 实为 **16** 而非 15（13 必备 + `filter_records` 别名 + 2 分析链）；③`app/` 改动文件实为 **6** 而非 7；④§4.5② 「未 import app 即可裸 import `core.tools.records`」措辞不准——需先 core-side `configure`（注册表要求），但 `app not in sys.modules` 成立。
7. **R7｜`documents.py:3-5` 的债注释未清（P1）**：`core/tools/documents.py` 顶部 docstring 仍写「`app.template_compare` … 本模块顶部回指它」，而 `:11` 已改为 import `core.tools.template_compare`。规格 §7-9 明确要求删掉/改写为「已消除」，**WP-S7-B 漏做**。0 行为影响（纯注释），但会误导下一位读者。同理 `core/tools/metrics.py:3` 指向已失效的「§6 D3」（P2）。
8. **R8｜流程债三项**：仓库**无 `backup/` 目录**（计划书 §10「P0 备份存在」字面未满足）；**无 S2–S6 handoff**（`docs/team/handoffs/` 由本包新建，历史件不补造）；**未做 git 侧任何校验**（`git status/diff/tag/log` 一律未运行，所有「哪些文件变了」的结论来自基线哈希比对 + mtime 枚举）。
9. **R9｜`FrozenReport` 与 `matplotlib` import 顺序**：`data_root()` / `report_factory` 必须在**函数内**取值；若未来有脚本在 `configure` 之前直接 import 渲染器，会得到 `package_not_configured`（实测复现过：`core/charts/renderers/matplotlib.py:17` 在 import 期调 `registry.charts()`）。
