## 2. 并行概览

```
G1  WP-S2-A  薄壳第一砖 + 客户包数据层            ← 全部包的前置，独占第一波
     │
     ├──────────────┬─────────────────────────┐
G2  WP-S2-B（records/locality/metrics 拆分）  WP-S2-C（去重剥离）      ← 文件零重叠，并行 2
     │                    │
     ├────────────────────┴───────────────┐
G3  WP-S2-D（events/documents 拆分）    WP-S2-E（执行器白名单化）      ← 文件零重叠，并行 2
     │                    │
G4  WP-S2-F  注册表收口 + app/tool.py 收成纯薄壳 + S2 门禁            ← 串行收口
```

| 波次 | 并行度 | 为什么 |
|---|---|---|
| G1 | 1 | A 立「薄壳第一砖」与包数据源，B/C/D 都要 `from core.tools...` 与 `vocabulary`；先立面无面可拆 |
| G2 | 2 | B 只动 `app/tool.py`+`core/tools/{records,locality,metrics}`；C 只动 `app/event_grouping.py`+`core/tools/dedup.py`。**交集为空** |
| G3 | 2 | D 动 `app/tool.py`+`core/tools/{events,documents}`；E 动 `app/tool_executor.py`+`core/tools/hints.py`。**交集为空** |
| G4 | 1 | F 要同时消费 D（域模块齐了）与 E（执行器读 hints），且 `app/tool.py` 只剩它一家改，收口不可并行 |

**硬约束**：`app/tool.py` 是全局唯一争用点，**同一波次只允许一个包持有它**（B 在 G2、D 在 G3、F 在 G4）。C、E 全程不碰它。

## 4. 决策（回答拆分时必须回答的四个问题）

### D1｜薄壳包为什么必须第一个？

因为 `event_analysis.py:76` 是 `from .tool import CLUSTER_TERMS`，而 `CLUSTER_TERMS` 必须同时满足三个互相拉扯的要求：
① 词表要搬出 `tool.py`（技术债基线 §2.5）；② `event_analysis.py:83` 用它的 `json.dumps(sort_keys=True)` 算 `rules_hash` 做**分类缓存失效判定**；③ `:246` 用 `list(CLUSTER_TERMS)` 当模型封闭枚举，**键序参与语义**。

任何"先搬文件、后补薄壳"的顺序都会在中间态出现 `ImportError`（直接炸穿 `analyse_events` 整条链），或者更糟——名字还在但内容/顺序变了，表现为"缓存全失效 + 模型枚举全变"这种不报错的静默事故。

所以 A 的第一件事是把 `CLUSTER_TERMS` 在原地改造成 `CLUSTER_TERMS = vocabulary.cluster_terms()`：**名字、位置、键序、内容四项全部不变**，只是值从代码字面量变成数据文件。同包内顺带立 `__all__` 薄壳契约（23 个名字）与 `core/tools/` 包骨架。

A 的两条硬证据：`G-RULES` 哈希 = `5dda8cc9…e2e687`（= 改造前实测值）、`G-GOLDEN` = `3f59d6c6…`（= 涵盖 `cluster` 与 `groups` 两段的产物指纹）。这两个值同时成立，才证明"搬了、但一个字都没变"。

> 说明：`app/tool.py` **收成纯薄壳**发生在 F（`DEFS` 只剩 3 个函数）。这是刻意的两步：A 立**面**（谁都能 import、搬到哪都不断链），F 收**体**（实现清零）。中间波次每个包搬完自己的域就当场补 re-export，薄壳面只增不减。

### D4｜去重剥离会不会碰 `event_analysis.py`，如果会，和哪个包冲突？

**按本方案：不碰，0 行。**

去重是三级串联（系统地图 §7.1.4）：① 本地 TF-IDF 0.65 归并（`event_grouping.py`）→ ② 模型边界判定（`event_analysis.py:107-219`）→ ③ TOP10 专属归并（`:168-214`）。本方案只剥离 ①，理由：

- ②③ 是**模型编排**（`invoke_agent` 循环 + checkpoint 断点续跑 + 分阶段失败预算），不是算法。把它抽成 `core/tools/dedup.py` 的纯函数意味着重写 `:107-219` 的 113 行编排逻辑——这直接违反"现有逻辑原样剥离、行为不变"和 L1 门禁（模型输出天然不可逐字节复现）。
- ① 与下游的唯一契约是**产物字段名**：`groups` / `member_scores` / `all_record_ids` / `borderline_candidates` / `method`。C 把这些逐字保留（含 `method.threshold`、`method.model_candidate_floor`、`method.representative`），`:114` 的 `local.get('borderline_candidates',[])` 就自然继续工作。
- ②③ 的**判定阈值与边界候选生成**已经数据化：`dedup.threshold=0.65`、`dedup.candidate_floor_ratio=0.6` 进 `template.data_contract`，C 从数据读 `*threshold*.6` 的 floor。这满足了"阈值进 data_contract"的真实意图，而不需要改编排。

**如果**队长坚持把 ② 模型边界判定也搬走，则必须改 `event_analysis.py`，此时冲突对象是：**S2 内无包与之冲突**（没有包持有该文件），但与 **S4（技能包）** 和 **S6（图编排/审校循环）** 会争用同一文件；且 S2 的 `G-GOLDEN` 无法覆盖模型段，需要另立 T 轨工作包与对照门禁（工作流 §8.2）。**建议：S2 只剥 ①，② 交 T1。**
