- **内容**：`arguments_schema` 现在是「`{'required': [...], 'properties': {'path': 'string'}}`」这种**类型名字符串**，不是合法 JSON Schema（`'string'` 应为 `{'type': 'string'}`）。真 schema 化后 `G-SPECS` 的 21 项序列化全变，必须 `--force` 重录；且 `app/workflow.py:226` 会把 spec 喂给模型 → 构成一次独立的模型输入变更。
- **S7 裁决**：不做（`任务分解-S7.md` §6 D6 取 (b)）。与 P7「零漂移」直接冲突，且不属 P7 范围。
- **实测证据**：
  ```text
  name import_records
  arguments_schema {'required': ['path'], 'properties': {'path': 'string', 'sheet_index': 'integer'}}
  SPECS 21 87405e5e86387b7fb3948b6ca373f9b968454ac845cced1771842cafe22c21cb
  ```
- **触发条件**：任一工具需要被外部 schema 消费方（OpenAPI 生成器、前端表单自动渲染、模型 function-calling 严格校验）直接使用时。届时需：①改 21 项 `arguments_schema`；②`gate_specs --force` 重录并写明理由（RISK-2 纪律）；③承认「机器稿可能重跑」（模型输入变了）。

## 五、台账使用纪律

1. **「已清」必须有可复跑的证据行**（哈希 / 退出码 / 用例名），不接受「看过了没问题」。
2. **「保留」必须写触发条件**，否则下一个人无法判断何时该动它。
3. **基线不得重录**（`gate_core_iso --record --force` / `gate_prompts --force` 同类）——重录即门禁自证循环，会让整条证据链作废（RISK-2）。
4. **发现的问题与「已修」严格分开**：P1/P2 是「发现未修」，不得在下一份报告里被写成「已清」。
5. **不补造历史**：N3 的 `backup/` 与 S2–S6 handoff 永远标「登记接受」，不打勾。
