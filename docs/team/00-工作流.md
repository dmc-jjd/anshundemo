## 2. 三层门禁（取代计划书里"hash 不变"的单层说法）

| 层 | 范围 | 判定 |
|---|---|---|
| L1 确定性 | 5 张 PNG、统计 JSON、TOP10 表、导入/过滤结果、来源绑定结果 | **逐字节 hash 相等** |
| L2 结构 | docx 段落树、槽位填充完整性、Schema 校验、事件组集合 | **结构等价**（diff 为空） |
| L3 文本 | Writer 生成的正文 | 指纹表 + 抽检，不做 byte diff |

> L3 不做 byte diff 的原因：文本由模型生成，同一输入两次调用不会同字节。任何要求文本逐字节不变的门禁都无法通过。

## 5. 派发规则

### 5.1 工作包五要素（缺一不派发）

```text
1 文件清单   ：精确路径，新增/修改/删除分别标
2 改动指令   ：逐条说明改什么、改成什么；存量代码给「源行号 → 目标写法」
3 禁改范围   ：明确不许碰的文件与符号
4 验证命令   ：可直接粘贴执行 + 期望输出
5 回滚点     ：git tag / commit
```

### 5.2 并行条件

两个 executor 只有在**文件零重叠**时并行。P5（提示词外置）天然单文件串行，只派 1 人。

### 5.3 审批粒度

**工作包级**：队长审工作包 → 用户审阶段。不做逐文件审批（否则每阶段几十次确认）。

### 5.4 弱模型补偿

- 所有设计决策由队长出，executor 只做「按清单替换」。
- 禁改范围显式列出，不靠 executor 自觉。
- 每个工作包的验证命令必须能一行跑完并给出可判定的输出。

## 6. 交接（handoff 五段）

每阶段结束写 `docs/team/handoffs/<stage>.md`：

```markdown
# Handoff: <stage>
## Decided   本阶段定下的关键决策
## Rejected  考虑过但否决的方案及原因
## Risks     下一阶段必须知道的风险
## Files     关键新建/修改文件
## Remaining 留给下一阶段的事项
```

队长在 spawn 下一阶段前必读全部既往 handoff，并把内容注入队员 prompt。

## 7. 执行纪律（Ponytail）

写码角色统一加载 `ponytail` 技能，并额外遵守本项目收紧条款：

- 搬迁类任务**禁止新增公开函数/类**，只允许移动代码 + 改 import。
- 迁移的代码**保留原有错误处理与校验**，不因"最小化"删掉。
- 旧模块保留 re-export 薄壳，调用方零改动。
- 新增的非平凡逻辑（分支/循环/解析/金钱/安全）必须留一个小测试。

## 8. 双轨：R 轨（纯搬迁）与 T 轨（新能力）

**2026-11-11 用户追加需求**：现有代码已包含「去重」与「分类」的算法与逻辑；重构后要把这两个能力**剥离成独立工具**，并**改用新算法**实现。

这条需求打破了「所有阶段产物 hash 不变」的单轨假设——换算法必然改变结果，L1 字节相等在这两处永远不可能成立。因此拆两轨：

| 轨 | 内容 | 门禁 |
|---|---|---|
| **R 轨** | S0–S7 的搬迁、外置、收口 | L1 hash 相等 / L2 结构等价 / L3 文本指纹 |
| **T 轨** | 去重工具、分类工具的剥离与重写 | **对照门禁**（见下），不走 L1 字节相等 |

### 8.1 T 轨的位置

插在 **S2（声明化）之后、S3（图表包）之前**，编号 T1。原因：工具库上移完成后才有 `core/tools/` 这个落脚点，去重/分类才有可能成为「独立工具」而不是又塞回 `app/tool.py`。

### 8.2 T 轨的对照门禁（取代 L1）

对同一份输入（P0 的 10 月全量数据）：

1. **旧结果**：用迁移前的实现跑一遍，产出 `去重前N条 → 去重后M条`、`每条记录的分类`，落盘成 `docs/team/baseline/{dedup,classify}-old.json`
2. **新结果**：用新算法跑一遍，同样落盘
3. **对照报告** `docs/team/verify-T1.md` 必须给出：
   - 去重：保留/丢弃条数、差异记录明细（最多列 50 条 + 总数）、差异归因（口径不同 / 算法不同 / bug）
   - 分类：混淆矩阵、每类准确/召回、变更记录明细
4. **人工抽检**：差异记录随机抽 20 条，用户或 verifier 判定哪边对
5. 判定：GO 需要「差异全部可归因」+「抽检无新增错误」

### 8.3 T 轨的设计约束

- 算法进 `core/tools/dedup.py`、`core/tools/classify.py`，**客户无关、0 业务词**
- 去重键、分类类别与关键词词典进 `template.data_contract` / `template.vocabulary`（沿用计划书 §4.1、§7）
- 旧实现保留 re-export 薄壳，R 轨其余部分零影响
- 新旧实现并存期间，用开关（例如 `manifest` 里 `tools.prefer`）切换，便于对照
