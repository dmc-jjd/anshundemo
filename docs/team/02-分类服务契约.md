# 分类服务契约（服务端 ↔ 客户端）

> 分工：**服务端（你的云服务器）**负责 微调 BGE + 半监督聚类 + 推理；**客户端（本仓库）**只做 HTTP 封装。
> 本文是双方唯一接口约定。客户端实现 `core/tools/classify.py`，服务端由你实现。

## 0. 已定决策（2026-11-11）

| # | 决策 | 来源 |
|---|---|---|
| 1 | 训练在云端 GPU 完成，模型目录由你提供 | Q1 |
| 2 | 类别体系**不固定为现有 12 类**，会扩充数据集重新训练 | Q2 |
| 3 | 发现新类别 → 人工 case 回流打标 | Q2 |
| 4 | 客户端只做推理封装，不做训练 | Q3 |
| 5 | 推理部署在你的私人云服务器 | Q4 |

## 1. 三条硬约束（客户端设计由此决定）

### 1.1 类别是**开放集合**，不是 12 类枚举

现状 `event_analysis.py:246,254` 把模型输出约束在 12 类封闭枚举内。新链路必须反过来：

- 类别列表**由服务端返回**，客户端不硬编码、不校验、不 fallback 到 12 类
- 客户端缓存 `GET /v1/categories` 的结果，只用于展示与校验拼写
- 服务端新增类别 = 客户端零改动

### 1.2 服务不可用**不能**让报告链路中断

报告产出是主链路，分类是增强。任何失败（超时/5xx/未就绪/限额）必须降级到**现有词典链路**，并在任务事件里落一条 `classify_degraded`。

### 1.3 推理必须**可离线复现**

远程服务 = 非确定性 + 版本漂移，直接违背 L1 门禁。解决办法复用本仓库已有的录制回放惯例（`data/artifacts/model_exchange-*.json`）：

| 模式 | 行为 | 用途 |
|---|---|---|
| `live` | 真实调用 | 生产 |
| `record` | 真实调用 + 落盘 `classify_exchange-<sha>.json` | 造 fixture |
| `replay` | 只读 fixture，**不联网** | 测试与门禁 |
| `fallback` | 不调用，直接走词典链路 | 服务不可达时的兜底 |

模式由环境变量 `CLASSIFY_MODE` 控制，默认 `live`；跑 pytest 时默认 `replay`（或 fixture 缺失时 `fallback`）。

## 2. HTTP 接口

Base URL 与凭据来自环境变量（`config.py` 白名单需新增，见 §6）：

```
CLASSIFY_BASE_URL   https://your-host/v1
CLASSIFY_API_KEY    <token>
CLASSIFY_TIMEOUT    30     # 秒
CLASSIFY_BATCH      100    # 单请求最大条数
```

### 2.1 `GET /health`

```json
{ "status": "ready", "model": { "name": "bge-ft-anshun", "version": "2026-11-20", "hash": "sha256:ab12..." }, "categories_count": 14 }
```

`status ∈ {ready, loading, degraded}`；非 `ready` 时客户端直接降级，不重试。

### 2.2 `GET /categories`

```json
{ "model_version": "2026-11-20", "updated_at": "2026-11-20T10:00:00Z",
  "categories": ["交通管理", "文化旅游", "教育医疗"] }
```

### 2.3 `POST /classify`

请求：

```json
{
  "model_version": "2026-11-20",
  "items": [
    { "id": "rec-000123", "title": "...", "summary": "...", "text": "标题\n梗概" }
  ],
  "options": { "top_k": 1 }
}
```

- `id` 由客户端生成，必须原样回传；客户端按 `id` 对齐，**不依赖返回顺序**
- `text` 是服务端的首选输入字段；`title`/`summary` 供服务端自行拼接或加权
- 单次 `items` 长度 ≤ `CLASSIFY_BATCH`

响应：

```json
{
  "model": { "name": "bge-ft-anshun", "version": "2026-11-20", "hash": "sha256:ab12..." },
  "results": [
    { "id": "rec-000123", "category": "交通管理", "confidence": 0.87,
      "alternatives": [ { "category": "社会治安", "confidence": 0.08 } ],
      "is_new_cluster": false }
  ]
}
```

字段约定：

| 字段 | 必需 | 说明 |
|---|---|---|
| `category` | 是 | 任意字符串；**允许出现训练集中没有的新值** |
| `confidence` | 是 | 0–1 |
| `alternatives` | 否 | top-k（`top_k>1` 时返回） |
| `is_new_cluster` | 否 | 聚类判为新簇（低置信 + 远离所有质心）时置 true，客户端据此标记「待人工分类」 |

### 2.4 错误语义

| HTTP | 客户端行为 |
|---|---|
| 200 | 正常；缺 `id` 的条目视为该条失败，其余照用 |
| 400 | 不重试，整批降级，落 `classify_bad_request` |
| 401/403 | 不重试，整批降级，落 `classify_auth_failed` |
| 429 | 退避重试 1 次，仍失败则降级 |
| 5xx / 超时 / 连接失败 | 重试 1 次，仍失败则降级 |

降级 = 走词典链路 + 落 `classify_degraded` 事件（含原因与模型版本）。**绝不抛异常打断报告生成。**

## 3. 客户端降级链（四级，沿用现有优先级）

```
人工覆盖 (human_category_overrides)
  → 服务端 /classify
    → 本地词典打分 (template.vocabulary.cluster_terms)
      → 标记「待人工分类」
```

前两级不参与自动判定：人工覆盖永远最高优先。

## 4. 人工回流（case 回流打标）

新类别靠人工发现。客户端负责**采集**，不负责训练：

### 4.1 落盘格式

`data/feedback/category_corrections.jsonl`（append-only，一行一条）：

```json
{"ts":"2026-11-20T10:12:00Z","record_id":"rec-000123","title":"...","summary":"...",
 "predicted":"交通管理","predicted_conf":0.87,"human":"道路设施","action":"relabel",
 "model_version":"2026-11-20","source":"ui"}
```

`action ∈ {relabel, new_category, exclude}`：
- `relabel` 改判到已有类别
- `new_category` 人工输入了一个服务端当前没有的类别 → 这就是**新类别候选**
- `exclude` 判定为不该参与分类（噪声/重复/无意义）

### 4.2 导出给训练

`scripts/export_feedback.py` 把 jsonl 聚合成训练集增量：

```
--since 2026-11-01 --out data/feedback/dataset-202611.csv
列：text, label, source(original|correction|new_category), record_id
```

你拿去云端并入数据集重训。**版本号由服务端回填到 `model.version`，客户端记录到每个任务的元数据里。**

### 4.3 客户端必须补的两处死接缝

W1 侦察发现 `human_category_overrides` 全仓库**只有读、没有写**。T1 要补上生产者：

- 人工改判时同时写 `human_category_overrides`（运行时覆盖）**和** `category_corrections.jsonl`（训练回流）
- 两者职责不同：前者影响当前任务结果，后者是长期数据资产

## 5. 验收（T 轨门禁）

不使用 L1 字节相等（服务端会变）。改用：

| 项 | 标准 |
|---|---|
| 接口兼容 | 契约测试用 mock server，覆盖 §2.4 全部错误码 |
| 降级正确 | 拔掉网络跑全链路，报告仍能产出，且落 `classify_degraded` |
| 回放一致 | `replay` 模式下同一 fixture 两次运行结果完全相同 |
| 质量 | 你提供标注集，客户端只负责统计准确率/混淆矩阵，不设定阈值 |
| 新增类别 | 服务端返回训练集没有的类别时，客户端不崩、能落盘、进「待人工分类」 |
