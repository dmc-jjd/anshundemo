## 3. 清债时的执行约束（读代码时发现，供队长排工作包）

### 3.1 `tool.py` 是唯一争用点
`安顺`/`西秀`/`舆情调性`/`CLUSTER_TERMS` 四个词的命中都落在 `app/tool.py`（:30、:40、:62、:168、:188、:191、:194）。
计划书 §4（工具库上移）与 §5.1（图表包上移）都要求改这个文件，§7.1/§7.2 的数据化也在这里落点。
**四类改造挤在同一文件，必须串行**，这是本次重构最大的排期约束。

### 3.2 必须先立 re-export 薄壳
`event_analysis.py:76` 的 `from .tool import CLUSTER_TERMS` 是运行期模块级 import。
一旦 `tool.py` 里删掉该常量而薄壳未就位，`_analyse_report_events` → `analyse_events` 整条事件研判链直接 ImportError。
计划书 §11 已有「旧模块保留 re-export 薄壳」的对策，此处必须有显式验收：`import app.event_analysis` 成功。

### 3.3 缓存指纹会被词典搬家污染
`event_analysis.py:83` 用 `json.dumps(CLUSTER_TERMS, sort_keys=True)` 的 sha256 作为分类缓存键；
`template_review.py:10` / `section_two.py:7-9` 另有 4 个 `POLICY_VERSION` 字符串。
词典改从 `template.json` 读之后，序列化形态（键序、嵌套层级）任何变化都会让存量任务的分类结果被判为失效。
**建议**：迁移后先跑一次「分类结果 diff 为空」对照（计划书 §11 已列此风险），再动缓存键算法。

### 3.4 标题字面量有两份副本
`chart_spec.py:11` 的 `TITLES` 与 `writer_tools.py:31` 的 `titles` 是两份独立的图表中文标题。
合并为 `template.charts[].title` 单一来源时，需确认两条渲染路径（Pillow / Matplotlib）读同一个字段，否则只清掉一处 grep 命中、问题仍在。

### 3.5 数字口径须先冻结再清债
本基线是**文本计数**，不是语义计数。若后续改动引入新的同义表述（如把「安顺」改成「本市」），grep 会显示为 0 命中但业务耦合并未解除。
建议队长在 S7 验收时补充人工复核（计划书 §10 只写了 grep=0）。

### 3.6 `export.py` 的归属未定，导致 3 个命中无法指派
`export.py:20`（封面标题）、`export.py:49`（属地槽位表）、`export.py:150`（演示稿标题）三处命中，
在计划书 §8 目标目录中**找不到 `export.py` 的位置**——它既不在 `core/` 下，也不属于 `packages/` 的三类资产。
在归属定下来之前，这三处无法指派给任何章节，标 `[待确认]`。
