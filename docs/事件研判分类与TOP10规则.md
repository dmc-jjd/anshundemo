# 事件处理与 TOP10 规则

## 已确认的 TOP10 定义

模板记录四个维度：入榜记录必须同时为负面且已预警；单位为去重后的具体事件；排序指标为每个事件内负面且已预警的原始记录条数，降序排列；每个事件仅一行，展示严肃、简明事件梗概和该计数。同值使用稳定事件 ID 顺序，不以原始标题排序，不用其他未预警记录抬高排序值。

模板结构字段：`top10_rule.scope=negative_and_warning`、`unit=deduplicated_event`、`ranking=negative_warning_member_count`、`direction=descending`、`display=serious_concise_summary`。确认模板时保存，预览表头为“序号 / 事件梗概 / 负面预警条数”。Writer 和 Word 导出从锁定事实里的 `top10` 取表格，不由 Writer 自行决定排名。

## 合并与人工兜底

标题与梗概先做本地词项向量匹配，达到阈值自动归入固定代表的事件组。低于阈值但达到模型候选下限的边界关系再交大模型比较代表内容；模型返回同一事件或不同事件时自动处理，只有明确返回 uncertain 并说明事实缺口时才送人工。模型候选下限目前为自动合并阈值的 0.6 倍，属于可校准的检索规则。大模型不通过成员链传递合并：并行批次中的来源组和目标组互不交叉，每次比较当前最终代表。

网络失败、格式错误、模型漏返回对象均属于机器处理未完成，进入可重试阶段，不伪装成人工待办。成功的模型判断逐批保存检查点，重试从已完成项继续。用户可在本期审核页修改向量阈值并重新分析；数据锁定后须新任务重新计算。

## 为什么曾有很多“待人工分类”

旧链路对 3,914 条负面或预警原始记录只做 10 类短词典匹配，未命中就直接派给人工。10 月旧样本有 1,466 条记录（约 37.46%）落入该组。它不是去重事件数：同一事件重复记录可能被重复计入。词典未覆盖寻人、首付退款、汉堡纠纷等表达，也缺少部分业务类别。

新链路按归并后的事件分类，优先使用来源有效类别和明确的本地规则；规则未覆盖或有冲突的事件交大模型按事件语义分类。只有模型仍无法分类的事件显示“待人工分类”，附具体原因及原文。词典未命中数量、模型待处理数量、人工不确定事件数和所含来源记录数分别记录，不能混为一个人工待办数量。

## 梗概与复核

模型根据事件内负面且已预警的成员标题与梗概撰写15—35字（含标点）的简短陈述，不复制口语、标签和情绪化标题。指控或诉求保留“反映 / 称 / 举报”等归因，禁止添加未经来源支持的数字。每条梗概引用该事件中符合入榜条件的记录。证据不足的梗概可由人查看来源后补充；模型调用失败的梗概留在机器待处理状态。

整体数据确认前须解决模型仍不确定的事件关系、分类与梗概。人工改变事件分组后，须更新分类和 TOP10 梗概，避免排名与成员版本不一致。第一部分其他范围（如负面或预警并集）不随 TOP10 的范围变化而被改写。
