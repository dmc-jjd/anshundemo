参考文件817行全部为“负面、是否预警=是”。当前1688组中有749组完全没有预警记录，其中631组只有一条未预警记录。因此 `1688 = 939 + 749`；1688与817不能直接当作同范围的去重准确率比较。这是报告业务口径未对齐，不能靠修改显示数字解决。

## 同范围的122净差

817行按网址、其次按精确原文标题回查，全部817行均匹配全量数据，0行未匹配。每条参考记录均落在一个当前组，当前覆盖749组。31个当前组各覆盖了不止一个参考标题，净合并68个参考标题；另外190个含预警记录的当前组，没有包含参考文件的代表行。

`939 = 817 - 68 + 190`，因此同范围净差122；总差 `871 = 749 + 122`。

“190组没有参考代表行”不等于190个真实新增事件：它们可能是参考文件已用其他代表行概括的重复传播，也可能是被参考整理剔除的内容。仅凭代表行不在组内，不能自动判定它们应合并或删除。“净合并68”同样不等于68次误合并。

例如参考文件把“竹荪种植大棚火灾致2人死亡”列为两个略有不同的标题，当前归为一个组；平坝矿山爆破、政府回应类诉求也出现多个参考标题落同一组。这说明两条链路采用的事件粒度确实不同。

## 算法和来源差异

当前工具使用的是标题+梗概的**双字词项TF-IDF稀疏余弦**，阈值0.65，并非语义嵌入模型。新记录只和固定代表比较；本地相似度候选下限是0.39，低于候选下限的表达变体不会自动进入同一轮候选。这会使省略主体、标签化标题、同事件的不同说法分开。当前3914条里有1416个单条组，显示分组碎片值得进一步校准，但单条组本身不能直接当作错误。

参考文件提供了改写后的规范事件标题、原文标题、类别、区县和重复标记；全量文件没有同样的重复标记列。参考817行中774行标“否”、43行仍标“是”，这些43行也被两个817总计计入。因此817并不是简单按“是否重复=否”就能复算的结果，不能把该文件视作严格无异常的机器真值。

上一轮26项检查只验证冻结数据内部统计与导出一致，没有验证与817业务基准口径一致。本轮补充了外部基准、范围和代表行匹配对账。
