# 安顺月报工作台 Demo

图表样式现在可在模板预览中查看、对照历史原图并更换；报告也可只重绘图表。任务详情新增Token输入/输出、缓存及费用估算，可修改单价与时段。历史未标明模型的费用保留待定。见 [图表与Token费用验收](docs/图表与Token费用验收-20261108.md) 和 [817与1688口径对账](docs/817与1688去重口径对比-20261108.md)。

本地工作台用于检查历史 Word 的固定文字与变化位置、处理全量 Excel、保存事件候选和人工决定，并导出带明确未填槽位的草稿。当前提供的是**可运行的部分实现**；审查、正式图表与终稿链路的限制见下方和[验收记录](docs/验收记录.md)。

## 启动

在本目录使用 Python 3.13：

```powershell
python -m pip install -r requirements.lock
python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

打开 [本地工作台](http://127.0.0.1:8765/)。当前机器已经运行服务时可直接打开。若 pip 无法访问包源，现有环境可直接启动；`requirements.lock` 只钉住直接依赖，尚不是完整传递依赖锁。

## 演示顺序

1. “模板比对”上传两份及以上不同报告（例如 6、7、8 月），第一份作为排版基准；本地比对后，模型结合全部原文、规则和本地候选重新制定完整语义模板。打开模型研判后模板，核对动态字段、来源和业务问题后整体确认。旧 8 月标色模板继续作为历史预览选项。
2. “报告处理”选择上述确认的结构化模板版本，上传 10 月全量 XLSX，明细工作表序号填 `3`。没有模型配置时任务显示公开保底路径。保底分别保留全量、正面、中性、负面、已预警，以及用户确认用于第一部分（四）的“负面 OR 已预警”行并集。任务记录依次列出导入、筛选、属地、关键词事件候选、向量跨组近邻、原字段分类读取、独立主题聚类和材料选择。
3. 在任务详情打开结果工件与日志。新任务使用固定代表向量自动归并；事件组、来源行、成员 ID 全部保存。历史两轮候选工具保留供对照。业务人员可执行合并、拆分、独立、排除或暂缓。确认事件组时要提交覆盖所有相关记录且不重复的组；`{"strategy":"accept_keyword_groups"}` 可作为人工明确接受第一轮分组的决定，需先检查第二轮跨组候选。
4. 确认并锁定本期数据后开始写作。结构化路径由程序计算数据字段，Writer 按槽填写分析文字并可调用冻结数据的只读工具；Matplotlib 绘制五张图并插入原 Word 图位。在“查看报告与缺失项”中补充实际期号、成文日期或缺失文字。人工补充在本地保存，不再发回模型；有缺失字段或图表时不开放终审。写作图会依次运行表达检测、格式审核员和内容审核员，按意见限次退修，再交人工终审；人工保存后不回模型。任务详情“双审核与人工终审”可查看原句、意见及退修记录。见[真实图与双审核验证](docs/真实LangGraph双审核与去AI表达-20261108.md)。

`data/` 保存 SQLite、上传文件和工件。刷新页面后任务 ID 和执行记录仍可读取。停止服务用终端 `Ctrl+C`，再执行上面的启动命令可继续查看已有任务。

## 模型配置与边界

所有角色和可执行提示词统一维护于 `app/agent.py`，包括模板分析、事件归并/分类/梗概、Writer及历史研究；不同报告可在同文件配置Writer差异。执行、Schema与工具仍分模块维护，见[Agent提示词维护说明](docs/Agent提示词维护说明.md)。历史研究本次实际耗时与费用见[日志核算](docs/历史检索耗时与费用核算-20261108.md)。

环境变量 `REPORT_MODEL_URL`、`REPORT_MODEL_NAME`、`REPORT_MODEL_KEY` 全部设置后可启用兼容 OpenAI Chat Completions 的动态规划。本地 `.env` 支持模型配置；模型调用的实际成功与失败以任务事件日志为准。模板模型失败或结构校验失败时保留本地结果，但阻断人工确认；任务页可重试，并复用通过校验的批次。工具超时由可终止子进程处理；第二轮近邻使用倒排索引和有界候选检索，阈值与时间窗口未用标注集校准。

API 文档在 [Swagger](http://127.0.0.1:8765/docs)。本机单人演示边界，不具备多用户权限体系。


## 结构化模板与 JSON Schema

新增链路：两份及以上不同报告比对 → 模型语义制定完整模板 → 来源及结构校验 → 结构化候选与 Schema → 审阅确认版本 → 按该版本字段填写 → Word 预览。详见 [结构化模板与Schema](docs/结构化模板与Schema.md)。报告页面可以显式选择确认后的模板，旧 8 月模板继续作为预览选项。

## 人工审核与自动归并

事件改为标题加梗概向量与固定代表比较后自动归并。本期结果在一个可视化数据审核页整体确认，再开放 Writer 和报告审核。模板也可通过正文预览确认，JSON Schema 留在高级详情。详见 [本轮修改和验证](docs/人工审核与自动归并改进.md)。

## 模板三轮纠正与流程计时

每个模板批次最多三轮（首次生成+两次纠正），反馈包含本轮全部校验问题及前轮历史。已通过批次保留，刷新和重试不重置失败批次的次数。三轮仍未通过进入“查看并处理模板异常”，展示原文、候选、问题和耗时；人工可修改字段、规则和来源，提交后必须重新通过校验才能继续。网络失败单列为调用失败，没有可读取候选时不会伪装成人工审核任务。

任务详情显示总耗时、自动处理、人工等待、重试等待；展开可看阶段和每轮耗时。计时持久化，模板确认/任务终审后停止；并发轮次不直接相加当作流程耗时。旧任务没有记录的历史时间明确标注，继续处理后开始记录。

异常接口：`GET /api/templates/{id}/exceptions`，`POST /api/templates/{id}/exceptions/{batch}/resolve`；计时接口：`GET /api/tasks/{id}/timing`。异常提交需要任务修订、输入引用、完整修正候选和原因；不支持跳过校验直接放行。

## 人工审核节点

人工兜底是每个节点的最后一步。关系判断全部完成后，系统直接采用人工分组，本地重算统计与排名，并进入剩余分类/梗概的人工处理，不再调用模型重新研判。已有分类与相同成员集合的有效梗概保留，合并引起的分类冲突或缺失梗概会明确显示。

审核修改自动保存为草稿，刷新可恢复；关系页默认只显示未完成项，底部下一步按钮直接定位关系、分类或梗概。全部审核项完成后才开放数据锁定。
