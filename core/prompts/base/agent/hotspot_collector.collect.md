任务：汇总最近3天中国要闻20条，按影响力+热度综合排序
要求：
- 另含可能影响中国的国际要闻
- 参考微博/抖音/头条热榜
输出：结构化列表（序号/标题/一句话摘要/类别/原文链接），只输出列表，不要分析
必须联网搜索

检索已完成，你只做筛选与排序：调用方已按 7 个类别逐条联网搜索（`after:` 锁定最近 3 天），
结果经「坏标题 / 低相关 / 站点排除 / 日期窗口」过滤与事件级去重后，放在 payload 的
`search_results` 里，每条一行：`[序号] 类别 | 标题 | 摘要 | LINK: <url>`。
候选集已按 `rerank_score×2+authority` 粗排、类别由查询来源**预标注**（可微调但倾向保留）。
你的任务是**从这些结果里挑出 20 条**并做最终排序，不是自己回忆新闻。

日期注入说明：本提示词不写死任何日期。调用方在 payload 里注入 `today`（今天，ISO 日期）、
`window`（`from` = today 减 3 天、`to` = today）、`item_count`、`categories` 与 `search_results`。
一律以 payload 的值为准，不得自行推算是哪一天，也不得把窗口外的事件算作「最近3天」。

硬约束（会被机械校验，违反即整份退回）：
- 每条的 `url` 必须**原样照抄** `search_results` 里某一条的 `LINK:` 值；不许新增、改写、拼接、
  缩短或"推测"链接。引用检索结果之外的链接会被判为编造，连链接一起作废。
- 不许凭记忆补充检索结果里没有的新闻、标题、摘要或类别。
- 同一事件只保留一条；同类占比过高时优先补足稀缺类别。
- 检索结果里无法判断是否属于窗口内的条目，宁可不选。

JSON 输出（只输出 JSON 对象，不要额外文字、不要 Markdown 代码块）：
{"items": [{"rank": 1, "title": "标题", "summary": "一句话摘要", "category": "类别", "url": "https://...", "source": "微博热榜"}]}

字段约束：
- `items` 恰好 20 条，`rank` 从 1 连续编到 20，按影响力与热度综合从高到低排列。
- `category` 只能取 payload `categories` 里的值（本提示词不写死类别清单，一律以 payload 为准）；
  涉及境外但可能影响中国的要闻，统一归入 payload `categories` 中表示国际的那一类。
- `summary` 为一句话（约 20—40 字），只陈述事实，不写分析、评价或建议。
- `url` 必须是 `search_results` 中某条的 LINK 原文；`source` 写该条的类别线索/站点名
  （微博热榜 / 抖音热榜 / 头条热榜 / 新闻站点），无则留空字符串。
- 条数、类别或链接不合格会被退回重做一次，第二次仍不合格则整份作废。
