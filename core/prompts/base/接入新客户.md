# 接入新客户（agent 操作手册）

> 读者是 **agent**，不是人。读完这一份就能在 `packages/<新包>/` 建出整套文件，不需要先理解编排架构，也不需要改 `core/`、`app/` 里的任何一行。

## 一、这份文档给谁用

维护者确认完模板之后，你接到的活是：为一个新客户建包。产出物固定为：

1. `packages/<新包>/manifest.yaml`
2. `packages/<新包>/template.json`
3. `packages/<新包>/prompts/index.yaml`
4. `packages/<新包>/prompts/roles.yaml`
5. `packages/<新包>/接入记录.md`（缺口表 + 问答 + 自检证据，格式见 3.4）
6. 第七章五条自检命令的原始输出

三条纪律，违反任一条产出不接受：

- **不许猜**：第二章的三样输入必须先读完。推不出来的才问维护者。
- **一问一答**：每个 ❓ 单独成问，一次只问一个；问题按第三章的五要素写全；拿到回答立刻落文件，再问下一个。
- **每条断言有命令**：写进文件的每个结论，都必须能用一条命令重跑复现。写「应该没问题」等于没做。

问题数量由缺口决定：三样输入齐、口径清楚的客户可能只剩 1 个问题（`agents:` 声明），口径不清的客户可能有 4 个。不要为了凑数问已经能推出来的项。

### 2.1 已确认模板（`template_version` 产物）

模板有三个面，各自的家不同：

| 面 | 内容 | 从哪读 |
|---|---|---|
| `blocks` | 段落块：`index` / `text` / `parts`；`parts` 里带 `field` 的位置就是动态槽 | 人工确认后的 `template_version` 工件（`app/api_views/template.py:121`），由维护者给引用 |

## 三、缺口分析（核心）

把下面的清单逐项对照 2.1–2.3 的读盘结果，判成三类，写进 `packages/<新包>/接入记录.md`：

- ✅ **已有**：输入里字面存在，直接抄。
- 🔶 **可推导**：按表里的推导规则能算出来，且能用命令复核；写进文件并注明依据，**不问**。
- ❓ **必须问**：两条都不成立，问维护者。

判定是机械的：一项只能落在三类之一；说「应该是」就是没判完。

| # | 必需项 | 判定 | 推导规则 / 复核依据 | 什么情况转 ❓ |
|---|---|---|---|---|
| 1 | package 名、report_type | 🔶 | 包名 = 目录名 = `manifest.package` = `template.json.package`（两个现成包都同值；不一致不会启动失败，但审计行与目录对不上）。`report_type` 取客户报告名称 | 客户同时出多种报告、本期只做一种 → 问做哪一种 |
| 2 | 必需列 `required_columns` | 🔶 | 导入器只校验这个清单，缺列抛 `missing_required_columns`（`core/tools/records.py:28-29`）。现成两包都是 `['标题','舆情调性']` | 首行里没有能判调性的列 → 问用哪列判调性 |
| 3 | 列映射 `column_map` | 🔶 | 首行中文列名 → records 英文字段；**键序就是 records 的字段序**（`tests/test_s2_manifest_vocabulary.py:86-103` 钉住，哈希门禁看不见这层） | 首行有映射表之外、但客户要求进报告的列 → 问映到哪个字段 |
| 4 | 摘要列 `summary_columns` | 🔶 | `[0]` 优先，缺失时取 `[1]` 并截 1200 字（`core/tools/records.py:44`）；某列不存在不会报错，取空串 | 首选列与兜底列都在首行里 → 问哪一列是正文摘要 |
| 5 | 工作表序号 `sheet_index` | 🔶 | 记在 `data_contract.sheet_index`。**该键目前无消费者**：实际 sheet 来自任务参数，缺省 3（`app/main.py:102`、`app/workflow.py:205`） | 目标表不是第 3 个、且客户会每期换位置 → 问固定哪一个 |
| 6 | 区县清单 `localities` | 🔶 候选 / ❓ 范围 | 候选 = 2.3 数据里出现的行政区写法（噪声很大，见下）；`resolve_locality` 只做词表子串匹配，要求**恰好命中 1 个**（`core/tools/locality.py:17-19`） | **辖区范围一律必须问**（见 3.1） |
| 7 | 类目词典 `cluster_terms` | 🔶 候选 / ❓ 口径 | 候选 = 模板图注字段名 + 数据 `事件分类` 列取值分布；键序 = 枚举序（`core/tools/vocabulary.py:63-65`）；词典打分 = 词表成员在 `title + 摘要前300字` 的出现次数求和取最大（`core/classify/dictionary.py:37-45`） | **分类体系/类目口径一律必须问**（见 3.2） |
| 8 | 去重参数（4 个） | 🔶 | `data_contract.dedup`：`threshold`、`candidate_floor_ratio` 必填无默认；`merge_rounds` 缺省 1、`merge_threshold` 缺省 0.5（`core/tools/vocabulary.py:68-84`）。现成两包都是 0.65 / 0.6 / 2 / 0.5 | 客户对「什么算同一事件」有明确口径且与 0.65 冲突 → 问 |
| 9 | 图表清单 `charts` | 🔶 | 从模板图注推导 `id/family/style/binding/unit/scope/axis_label`；`manifest.charts.use` 必须与 `template.json` 的 `charts[].id` 同集合（A 包由 `tests/test_s3_chart_registry.py:29` 钉住） | 模板里有图的位置但看不出画什么 → 问 |
| 10 | `agents:` 声明 | ❓ | 无证据可推 | **一律必须问**（见 3.3 与第四章） |
| 11 | 提示词是否需要覆盖 | 🔶 | 默认全部继承基座，一个都不写（第五章） | 客户对口径/口吻有硬要求 → 问要改哪几条 |
| 12 | 报告月份/期号/成文日期来源 | 🔶 | 来自任务参数 `report_month` / `issue_number` / `publication_date`（`app/main.py:144`）；期号可从报告标题推出（`2026年第99期` → 99，`tests/test_report_parameters.py:24-26` 钉住） | 客户报告标题不含期号 → 问期号从哪来 |

### 3.1 ❓ 辖区范围（localities）

- **为什么需要**：`resolve_locality` 只用这份词表做子串匹配（`core/tools/locality.py:17`），词表外的地名不会出现在属地统计与属地图里。
- **不给会怎样**：命中 0 个或 ≥2 个都进 `needs_review`，第一部分属地表空、属地图无数据，且**不报错**。
- **默认值**：没有。不能拿 A 包的八区县顶替——那是另一个客户的辖区。
- **候选从哪推导**：扫数据的行政区写法（下面是噪声候选，只用来提问，不要直接落文件）：

```powershell
@'
import sys, re, collections
from core.tools.ooxml import read_xlsx
b = read_xlsx(sys.argv[1], sheet_index=int(sys.argv[2]), max_rows=2000)
hdr = b['rows'][0]['cells']; ti, si = hdr.index('标题'), hdr.index('摘要')
pat = re.compile(r'[\u4e00-\u9fa5]{2,6}?(?:自治县|县|区|镇|街道|开发区)')
c = collections.Counter()
for r in b['rows'][1:]:
    cells = r['cells']
    text = (cells[ti] if ti < len(cells) else '') + ' ' + (cells[si] if si < len(cells) else '')
    c.update(pat.findall(text))
print(c.most_common(40))
'@ | & $py - $xlsx $sheet
```

实测（A 包 10 月数据前 2000 行）：候选里既有 `西秀区(74)`、`普定县(38)`、`黄果树景区(46)` 这种真辖区，也有 `其余地区(71)`、`省的北部地区(48)`、`位于黄果树景区(32)` 这种垃圾，还有 `安顺市西秀区(19)`、`安顺市关岭自治县(16)` 这种**全称写法**。所以候选只能当提问素材。
- **影响面**：`resolve_locality` 的未解项、报告属地统计口径、`locality` 图。
- **问法（五要素齐）**：
  > 这份报告的辖区范围是哪几个行政区？我给不出默认值——词表外的地名不会进属地统计，命中 0 或 ≥2 都落人工确认。候选是数据里扫出来的这批（含 `其余地区` 这类非地名噪声，已标出）。请给 ①辖区全名单 ②每个辖区的**数据写法**（全称/简称/别名，例如 `西秀区` 在数据里还写成 `安顺市西秀区`）③跨区与不明怎么记。影响面：属地表、属地图、属地未解项数量。

### 3.2 ❓ 分类体系（cluster_terms）

- **为什么需要**：类目名是报告「事件分类」图与事件分类结果的取值集合；词典级的判据是词表成员出现次数之和取最大，**全 0 命中就判不出来**。
- **不给会怎样**：`dictionary_no_hit` → 事件分类列空、事件全落人工确认；流程照常走完，**不报错**。
- **默认值**：没有。不能抄 A 包的 12 类目。
- **候选从哪推导**：数据 `事件分类` 列的取值分布 + 模板图注字段名 + 摘要高频词：

```powershell
@'
import sys, collections
from core.tools.ooxml import read_xlsx
b = read_xlsx(sys.argv[1], sheet_index=int(sys.argv[2]), max_rows=2000)
hdr = b['rows'][0]['cells']; ci = hdr.index('事件分类')
c = collections.Counter()
for r in b['rows'][1:]:
    cells = r['cells']
    c[(cells[ci] if ci < len(cells) else '').strip() or '(空)'] += 1
print(len(b['rows']) - 1, 'rows')
print(c.most_common(30))
'@ | & $py - $xlsx $sheet
```

实测（A 包 10 月数据）：`1999 rows`、`[('(空)', 1999)]` —— 源数据分类整列为空。这种情况候选**只能**从模板图注（`template.json` 里 `theme` 图与 `事件分类` 字段名）与摘要高频词推，口径必须问，不许自己编 12 类。
- **影响面**：`classify_records`、`cluster_event_themes`、`discover_topics`、`theme` 图、事件清单的分类列。
- **问法**：
  > 分类体系用哪一套、几个类目？默认值没有——词表与类目不匹配时分类会静默落空（本月数据源分类列实测全空，候选推不出来）。候选可从模板图注与摘要高频词里列给你核对。请给 ①类目名全名单（写入顺序即模型枚举序）②每个类目下的**数据里真实出现**的说法（做词表成员）③不确定的怎么处理。影响面：事件分类、主题聚类、分类图、事件清单呈现。

### 3.3 ❓ agents 声明（要做哪些步骤）

- **为什么需要**：这一段直接决定哪些流程步骤跑、哪些整段跳过（第四章）。
- **不给会怎样**：不写 = 9 个角色全启用，历史调研会联网检索、两位审核员会各跑一轮。
- **默认值**：不写 `agents:`（全部启用）。这也是老包兼容语义。
- **候选从哪推导**：没有。没有任何输入能证明客户要不要历史调研/双审/事件研判。
- **影响面**：图结构（节点被裁 + 前驱改接）、耗时、外部请求、审核轮数、人工确认点。
- **问法**：
  > 这份报告要不要历史调研（会联网检索并核实地方事实）？要不要格式与内容两位审核员？事件研判（同事件判定/分类/梗概）要不要？默认是不写 `agents:`、9 个角色全启用。你的回答会直接决定图里哪些节点被裁掉，以及本次任务是否产生外部请求。

## 四、`agents:` 怎么声明（新能力，重点）

`manifest.yaml` 的 `agents:` 是**能力开关**：客户包只写角色 id，角色驱动哪一步由基座决定（`core/agent_steps.py` 的 `ROLE_STEPS` / `INLINE_STEPS`）。

九个可裁角色与各自的步骤：

| 角色 id | 驱动的步骤（图:节点） | 不声明（且无人替代）时会发生什么 |
|---|---|---|
| `template_analyst` | template:`local_compare_and_analysis` | 模板比对与结构化分析整段不跑；该链在 `BYPASS=None` 的节点上结束 |
| `data_processor` | report:`data_processing` | 工具循环整段不跑（导入/筛选/属地/候选/去重/分类/聚类/选材全部不发生），前驱改接到 `await_data_review` |
| `event_judge` | report:`event_analysis` | 见下方「共用节点」说明 |
| `event_classifier` | report:`event_analysis` | 见下方「共用节点」说明 |
| `event_summarizer` | report:`event_analysis` | 见下方「共用节点」说明 |
| `writer` | writing:`write_draft` | 正文撰写整段不跑 |
| `historical_researcher` | **内联**在 writing:`write_draft` 内 | 历史调研整步不跑（不联网、不查历史），`write_draft` 其余部分照跑 |
| `format_reviewer` | writing:`format_review` + writing:`final_format_review` | 两次格式审核都不跑 |
| `content_reviewer` | writing:`content_review` | 内容审核不跑 |

规则（全部来自 `core/agent_steps.py`、`core/manifest.py`，可用 `& $py -c "import app"` 复现）：

- **不写 `agents:` = 全部启用**（9 个角色都参与），老包兼容。
- **写了 = 只跑列出的角色**；未列出角色驱动的节点整段裁掉，前驱按 `BYPASS` 改接到后继（`core/agent_steps.py:58-65`）。
- **`agents: []` 等于不写**：空列表 falsy → 仍解析成「全部启用」（`core/agent_steps.py:81-84`，实测 `len(enabled_agents(空列表)) == 9`）。没有「一个角色都不跑」这种合法配置。
- **`event_judge` / `event_classifier` / `event_summarizer` 三个共用 `report:event_analysis` 一个节点**：只要声明其中之一，整段 `event_analysis` 仍会跑（裁节点看的是「这个节点有没有任一驱动角色在名单里」，`core/agent_steps.py:151-157`）。要整段跳过必须**三个都不声明**。
- **声明里出现 `roles.yaml` 没有的角色 → 启动即失败** `manifest_unknown_agent:<id>`（`core/agent_steps.py:95-100`，实测 `ValueError: manifest_unknown_agent:nope`）。别指望它被静默忽略。
- **声明了 `agents:` 但 `prompts/roles.yaml` 不存在 → `manifest_agents_unverifiable:<包名>`**（`core/manifest.py:58-60`）。
- 不在 `ALL_AGENTS` 里的角色（`writer_data_planner`、`hotspot_collector`）**`agents:` 开关不了**：它们不驱动可裁步骤，声明与否都不改变它们是否被调用（`core/agent_steps.py:41-54` 只把 9 个角色纳入调度）。

## 五、提示词覆盖

- 基座 34 条在 `core/prompts/base/agent/`，键名 = 文件名（`writer.analysis` ↔ `writer.analysis.md`）。
- 包内放**同名文件**（`packages/<新包>/prompts/agent/<key>.md`）并在 `prompts/index.yaml` 的 `agent_prompts` 里声明该相对路径，即覆盖基座；`provenance()` 显示 `package`。
- **不写 = 继承基座**（`base`）。**加客户默认一个提示词都不写**——`packages/demo_b/prompts/agent/` 有 10 个文件，`packages/anshun_monthly/prompts/agent/` 目录根本不存在（34 条全部继承基座）。
- `index.yaml` 四个顶层键必须齐：`agent_prompts` / `template_policy` / `report_prompt_profiles` / `default_prompt_profile`，缺一个就 `prompt_index_missing_keys:<键>`（`core/prompts/registry.py:102-104`）。
- 五个键是 **import 期硬依赖**（`core/agent.py:31-35` 在模块级取 `AGENT_PROMPTS[...]`）：`historical_researcher.plan`、`historical_researcher.research`、`writer.analysis`、`writer.outlook`、`template_analyst.template`。`index.yaml` 不声明它们，`import app` 直接 `KeyError: 'unknown_agent_prompt:<key>'`。
- 声明的键在包内和基座都没有对应文件 → `prompt_missing:<key>`（`core/prompts/registry.py:93`）。
- 最简单的做法：**复制 A 包的 `index.yaml`，只改 `report_prompt_profiles` 的 profile 名与 `default_prompt_profile`**；`agent_prompts` 34 行原样保留。
- 字节口径（`core/prompts/registry.py:15-21`，`tests/test_s7_package_contract.py:104-119` 钉住）：UTF-8 **无 BOM**、`\n` 换行、正文 + **恰好一个**结尾 LF。写文件用 `write_bytes`；不要用 `write_text`（Windows 默认转 CRLF，`\r` 会进正文并改指纹）。

## 八、常见错误清单

| 现象 | 原因 | 修法 |
|---|---|---|
| 以为关了属地/分类/去重，模型仍能调对应工具 | `features` 开关写成 `enable: false`。判定是 `config.get("enabled") is False`（`core/tools/registry.py:139`），键名写错 = 不生效，**不报错** | 统一写 `enabled:` |
| `prompt_index_missing_keys:template_policy`（或 `agent_prompts` / `report_prompt_profiles` / `default_prompt_profile`） | `index.yaml` 缺四个顶层键之一（`core/prompts/registry.py:102-104`）。注意这是**顶层键**错，不是某条提示词缺项 | 补顶层键；`template_policy` 可以写 `{}`（demo_b 如此） |
| `prompt_missing:<key>` | `index.yaml` 声明了该 key，但包内与基座都没有对应 `.md` | 补文件，或从 `agent_prompts` 删掉该行（后者仅当没有代码调用它） |
| `KeyError: 'unknown_agent_prompt:<key>'` | 代码要用的键没在 `agent_prompts` 里声明；五个 import 期硬依赖键尤其致命（`core/agent.py:31-35`） | 照 A 包的 34 行声明补齐 |
| `manifest_unknown_agent:<id>` | `agents:` 里写了 `roles.yaml` 没有的角色（`core/agent_steps.py:95-100`） | 在 `roles.yaml` 补该角色，或从 `agents:` 删掉。不要指望静默忽略 |
| `manifest_agents_unverifiable:<包名>` | 写了 `agents:` 但 `prompts/roles.yaml` 不存在 | 建 `roles.yaml` |
| 事件分类整列空、事件全落人工确认，且**没有任何报错** | 词表与类目名不匹配 → 词典全 0 命中 → `dictionary_no_hit`（`core/classify/dictionary.py:40-43`） | 用数据里真实出现的说法做词表成员；跑一次分类看命中率 |
| 属地命中 0、属地表空 | `localities` 的写法与数据写法不一致。匹配发生在**别名列表**上（`any(w in text for w in ws)`），要求恰好命中 1 个（`core/tools/locality.py:17-19`）。实测数据同一辖区有多种写法（`西秀区` / `安顺市西秀区`），只写一种就会漏 | 把数据里出现的写法都放进该区县的别名列表 |
| `manifest_missing_keys:<键>` | `manifest.yaml` 缺 `package`/`report_type`/`version`/`template`/`prompts` 之一（`core/ports.py:242, 284-286`） | 补齐五个 |
| `prompt_role_invalid:<角色>` | `roles.yaml` 的角色不是恰好 `{responsibility, boundary, output}` 三键、或值不是字符串（`core/prompts/registry.py:119-123`） | 每角色恰好三键，值全部写成字符串 |
| 提示词指纹漂移、正文里混入 `\r` | 用 `write_text` 写文件，Windows 默认 CRLF；注册表按字节读、不做换行翻译（`core/prompts/registry.py:15-21`） | 一律 `write_bytes` + `\n`，正文 + 恰好一个结尾 LF，UTF-8 无 BOM |
