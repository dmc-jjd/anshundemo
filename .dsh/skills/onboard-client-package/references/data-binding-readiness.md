# 数据字段绑定检查

适用于新建客户包、未确认模板优化、现有客户包模板更新，以及提示词完成后的交付。绑定由建包 agent 完成；业务测试仍由用户亲自操作。

## 补充计算工具的代码位置

已有能力直接配客户绑定；新增能力先取得用户对具体工具的开发同意。获准后按以下位置实现，不能只改目录说明或提示词就宣布工具可用。

| 内容 | 必须落点与要求 |
|---|---|
| 通用计算声明、参数与校验 | `core/frozen_report.py::Calculation`：声明 metric 及必要参数、类型、默认值和合法组合；参数名称不含客户专名。 |
| 通用计算实现 | `core/frozen_report.py::FrozenReport.calculate()`：接入实际运算，基于冻结事实取数，返回 `value`、`source_refs`、`calculation`；结果类型必须符合模板字段 schema。复杂逻辑可放 `core/` 内通用模块，由这里调用。 |
| 模型可见的能力说明 | `core/frozen_report.py::CALCULATION_CATALOG`：说明输入、统计范围、分母、去重及输出。不能只有目录条目却无实现，也不能实现了却未入目录。 |
| 确认阶段可选绑定 | 核查 `app/template_review.py::available_bindings()`、`binding_allowed()`：现有入口自动读取目录并使用 Calculation 校验，一般无需额外注册；新增参数必须能保留并通过这条链路。 |
| 客户字段与业务参数 | `packages/<包>/calculations.yaml`：字段 id → 通用 metric + 参数。客户媒体级别映射、平台集合、展示规则、呈发对象等配置属于客户包，不写入基座通用算法。涉及输入列时同步核查该包 `template.json` 的 `data_contract`。 |
| 写作执行链路 | 核查 `app/structured_writer.py::field_calculation_spec()` 与 `app/writing_pipeline/calculations.py::calculation_for()` 能读取并执行包绑定；不得向旧 `KNOWN` 添加客户字段映射。 |
| 自动验证 | 在 `tests/` 添加或扩展对应计算、绑定链路测试；用合成冻结数据验证正确值、范围/去重、缺输入与空数据、结果 schema、来源引用，使用项目定向离线测试入口。不能靠真实业务报告试跑代替。 |

上述计算能力与运行时工具是两个入口：字段 metric 不因新增计算就去 `core/tools/registry.py` 注册或扩充 `manifest.yaml tools.allow`。只有确实需要模型通过运行时函数调用的新工具，才按主手册 13.2 的 `core/tools/` 实现、registry 参数声明与客户白名单流程另行接入；不能混用两套注册方式。

交付前核实“声明 → 实现 → 目录 → 确认可选/校验 → 包绑定 → 写作计算 → 离线测试”全部连通，并在客户接入记录列出修改文件、受影响字段与验证结果。已确认模板仍不修改；通过包配置补绑定。本文说明实现位置，不构成新增工具开发授权。

## 检查流程

1. 固定 package、task_id 和模板工件引用；人工草稿存在时读 `/draft` 的生效 definition。逐项列出所有 `owner=data` 字段：**块编号（使用 blocks.index 原值，不加一）**、id、名称、semantic/rule/format、来源、统计范围、单位、返回值类型。
2. 按 `app/writing_pipeline/calculations.py::calculation_for` 的真实优先级检查有效配置：运行计划 → 旧 KNOWN → `field_calculation_spec`（字段 metric binding 优先于包映射）→ 旧 top10_events / calculate_metrics binding。建包完成不能依赖尚未产生的运行计划。`binding:null` 可能已有有效包映射；binding 非空也可能是无效参数，不能只数 null。
3. 已有能力由 agent 自行配置到本客户包 `calculations.yaml`，校验 `Calculation` 参数和实际结果 schema。旧 `{tool,path}` 要核查该 path 真能从冻结 metrics 取得。不要用 `constant` 填动态统计、不把 data 改成 writer 回避工具缺口、不将历史数值当本期数字。
4. 没有合适工具时停止依赖该能力的后续步骤，先按 [工具缺口交接规范](tool-extension-handoff.md) 保存“缺口与工具方案”文档并向用户提供链接，再询问开发授权：用途、输入列、筛选和去重规则、输出类型、涉及字段、已有报告影响。由用户指定的 agent 获准后实现通用工具；建包 agent 收到实现物证后再补客户绑定与验证。统计口径不清先问口径，不能自行猜测。其它独立字段仍可继续核对。
5. 未确认候选在交用户亲自确认前完成这一检查；已确认模板只补包配置，不修改确认工件、不另换确认版本。包配置不是按模板隔离的，核对同包旧字段语义，说明影响。
6. 用本地合成冻结数据执行相关计算、校验返回类型及字段 schema，覆盖筛选/去重、空数据和日期变化。使用现有明确的测试工具，不构造真实报告、不调用付费模型、不代跑业务测试。绑定检查通过不等于业务验收通过。

## 交付门槛

将本次绑定核对结果纳入 [执行闭环与交接检查](execution-gates.md) 的data_bindings覆盖项，缺口同时进入issues并给具体下一动作。新增/合并字段后还要核对section_two.field_roles、outlook_fields与实际字段ID；模板展示正常、包检查通过不保证写作角色已接通。包内增加新字段映射前核对旧模板同名字段语义，不为当前候选覆盖旧模板角色或重绑已有报告。

在客户接入记录中保存字段清单和验证结果，区分已绑定、缺工具、待确认口径、缺必要输入。报告月份、期号、成文日期是用户任务参数，提示清楚，不把“缺输入”说成“缺工具”。

尚有无有效绑定的 data 字段或已知计算类型不匹配时，状态为“待绑定处理 / 待工具开发授权 / 待口径确认”，不得交付为“待用户业务测试”。界面允许选择模板只说明工件可用，不说明全部数据已可计算。

只有这些检查和提示词技术自检完成后，才交用户测试步骤。交付说明应列数据字段总数、有效绑定数、未解决数及输入要求；不得承诺“全部由数据规划器补齐”或“尚缺绑定属正常、不影响生成”。规划器只在已有目录内尝试映射，无法发明运算，也无法保证每个字段成功。
