# 计算与图表工具缺口交接规范

## 先写文档，再请求授权或交接

发现现有目录不能表达字段计算、图表数据或图表呈现要求时，建包 agent **必须先产出项目文件并给用户可点击链接**，不能仅在聊天中描述缺工具后要求确认。格式沿用“缺口与工具方案”：目标与基准、缺口表、现有能力不足说明、通用扩展与影响、验证与交接。文档至少完整到另一位 agent 不读建包聊天也能接手。

建议保存 `packages/<包>/工具缺口与扩展方案-YYYYMMDD.md`；若项目已指定交接文档路径，在原文档中补充并保留修改记录，避免并存互相冲突的方案。不保存到 Obsidian。文档中的历史内容是依据，不能自动成为授权。

## 文档模板

```markdown
# <客户包/模板> 计算与图表工具缺口及扩展方案

目标：package、task_id、模板名、候选/确认 ref、读取时间。
基准：确认工件是否只读、字段总数/已有有效绑定数/缺失数；图表数量/已有能力/缺口。
状态：待口径确认 / 待开发授权 / 已授权待实现 / 实现待核验 / 已完成绑定（按实际填写）。

## 缺口及拟补能力

| 块 | 字段或图表 id / 名称 | 拟补通用能力 | 需要明确的口径 |
|---|---|---|---|
| 原始块编号 | 真实 id 与名称 | 泛化算法/图表类型，不使用客户专名 | 来源列、筛选、分母、去重、单位、排序、日期、空值/缺输入处理；未定项明确标注 |

## 现有能力为什么不足

逐项对应真实目录、schema、实现位置；说明哪些已有能力可复用，哪些无法表达，不能仅因字段名不同就新增工具。

## 通用扩展方案与影响

- 输入与输出：数据列/参数、结果类型与字段 schema；图表说明数据绑定、图种/样式、单位、排序、空数据与版式槽位。
- 分层与修改位置：基座泛化算法/参数/目录/注册；客户包字段绑定、词表、平台集合、范围及样式。计算按主手册13.2.2；图表按13.1定位实际入口，不能套用计算的注册方式。
- 复用方案：合并可共享的字段/图表需求，列出能力与字段对应关系；不要每个客户字段单独造算法。
- 兼容影响：同包旧模板后续生成、其他包、已有报告；确认工件与旧报告引用保持不变，存在限制如实写明。
- 待确认事项与授权：记录用户已确认口径及范围；未确认不能当事实，开发授权与口径确认分别记录。

## 验证与交接

- 实现验收：正例、筛选/去重、边界/空数据、缺输入、输出类型、来源引用；图表补数据序列、绘图/导出及槽位检查。
- 验证方式：定向离线测试与合成数据；不得代跑用户业务报告或付费模型。
- 实现方交回：修改文件/符号、metric或图表id/参数、实际测试命令与结果、绑定示例、兼容限制及未完成项。
- 建包 agent 接回：核验实际代码与测试物证，填写包绑定/图表声明，重读生效配置并验证；全部缺口解决后再交用户测试。
```

## 分工与回接

建包 agent 负责识别缺口、产出上述文档、已支持能力的包内绑定，以及实现后的回接核验。用户可以将文档交给专门的“计算＋图表工具增加 agent”负责代码；不强制由建包 agent 开发。用户若已明确授权本次建包 agent 实现，则直接执行，不重复申请同一授权。

本 skill 不自动创建聊天、派遣 agent 或向其它聊天发送消息。用户另行分配时，状态留“已授权待实现”并保存当前候选；工具缺口未解决前不诱导确认模板或进入业务测试。其他独立工作可继续。

工具实现方不能代替用户确认模板或代替建包 agent 宣告绑定完成。建包 agent 不以“另一个 agent 说已完成”作为证据：应核对已落盘代码、工具可达性、参数/结果类型、定向测试结果与客户绑定，更新缺口文档和接入记录。仍缺口径或验证时标明未完成，不交给写作规划器兜底。
