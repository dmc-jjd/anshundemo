# 字段关联与实际请求核验（建包必做）

字段绑定检查之后、用户亲自确认之前，agent 必须交付字段关联表，并在模板预览的「字段关联组」中供用户审阅。不能只写“上下文保持一致”。

先按 [执行闭环与交接检查](execution-gates.md#历史报告对照与字段关联) 逐节对照全部历史报告，区分“同案例写作组、统计口径一致、材料集合共享、前瞻研究共享”。有几组案例不能证明关联覆盖完整；关系不存在或暂缺动态查询支持时必须给依据及下一动作，不能仅加标识宣称已实现。

## 交付内容

每组列出名称、成员字段及角色、共同主题/案例、材料范围、数据口径、生成与审核要求。重点检查：

- 主题—背景—细节：共同使用一个主题；背景不重复全月统计；不同组不重复选题。
- 案例—研判—建议：共享同一案例正文与来源；建议服务当前客户，不跳到另一城市事件。
- 标题列表—重点标题—传播计数：先按地域、调性、业务筛选候选，再选择与计数；账号属性不能代替事件性质。
- 媒体机构—报道条数—媒体示例：区分机构与平台账号；示例与计数使用相同过滤和机构别名表；不为追平历史数值擅改口径。

未确认候选可通过 `/api/templates/{task_id}/definition` 的 `writing_groups` 保存（带 expected_revision），字段必须存在，禁止重复归组。用户亲自审阅并确认模板后，再继续提示词。不得由 agent 代点确认。

新增章节先落真实正文块和字段、同步Schema，再保存组；数据字段用计算绑定保证口径，不能为了组标识改成writer。纯数据关联不强塞进至少需要一个writer成员的组。前瞻组必须验证研究与引用门禁仍有效；没有验证时保留原前瞻流程，不能以通用joint请求替代。

界面核验先读API的实际members，再看复选状态。未选字段只是候选，不能因月份等无关候选排在前面便误改后台组。已关联成员默认可见、其它候选折叠，核对正文标识和关闭重开；验证只显示或改了组名不够。

已确认模板不可改、不得另换确认版本。仅在用户授权优化写作流程时，为现有客户包准备 `writing_contracts.yaml`，用准确 template_ref 隔离覆盖；新任务会快照契约。不能给旧冻结任务写入新契约、开启去重或重绑报告。

## 实际执行验证

用合成数据与本地模型适配器检查请求，不运行用户业务模型：

1. 关联字段是否在同一次 writer 请求中出现，且携带各自 semantic/rule、共同证据和完整相关模板片段。
2. 已写机器正文是否作为 existing_values 传入；人工私密正文仅传保护占位和状态，不向模型披露原文或引用，不进入可修改范围。
3. 数据字段是否使用最终有效计算定义；writer_calculation_plan 是否记录契约覆盖后的口径。
4. 严格查询为空时不得悄悄放宽地域、调性或回退全量；给出材料缺口并跳过写作。仅显式 allow_external_research 的外部案例组允许使用获授权检索工具补证。
5. 双审与退修是否获得整组上下文；logic_replacement 可以替换机器引错案例的日期，但新增数字必须有给定来源，程序统计与人工字段仍受保护。

仅检查提示词出现“按案例写”不算通过。交付合成请求证据与未验证项，业务报告测试仍由用户执行。

## 能力缺口

客户口径、字段关联、机构别名写在客户包，不把客户名或字段ID硬编码进基座。目录不足时先按主手册要求输出《缺口与工具方案》，说明通用扩展及影响，取得具体开发授权后再改；可以交给单独的计算/图表 agent 实现。

名称无法可靠归一时列出原始记录ID和待核实名称，不把未知账号当成一家机构，不依据历史报告家数倒推合并。

用户已确认的媒体机构口径：以原始“作者”为主，作者空值以同一行“来源信息”补充；已知机构名加明确地区/栏目后缀可归并本名，例如羊城派、羊城派-河源、羊城派-综合均归羊城派。不得因名称相似误合并独立机构；报道条数仍按原始明细。兜底后仍为泛平台名称的才列待核对。不因这一口径更新重建已确认模板，新建报告任务采用契约快照。
